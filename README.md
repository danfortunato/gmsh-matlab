# gmsh

A MATLAB binding for [gmsh](https://gmsh.info) built as a single MEX file.
Provides the full `gmshc.h` API surface (~377 functions) via idiomatic
dot-syntax that mirrors the Python wrapper:

```matlab
gmsh.initialize();
gmsh.model.add("square");
gmsh.model.geo.addPoint(0, 0, 0, 0.1, 1);
gmsh.model.geo.addPoint(1, 0, 0, 0.1, 2);
gmsh.model.geo.addPoint(1, 1, 0, 0.1, 3);
gmsh.model.geo.addPoint(0, 1, 0, 0.1, 4);
gmsh.model.geo.addLine(1, 2, 1);
gmsh.model.geo.addLine(2, 3, 2);
gmsh.model.geo.addLine(3, 4, 3);
gmsh.model.geo.addLine(4, 1, 4);
gmsh.model.geo.addCurveLoop([1, 2, 3, 4], 1);
gmsh.model.geo.addPlaneSurface([1], 6);
gmsh.model.geo.synchronize();
gmsh.model.mesh.generate(2);
gmsh.write("square.msh");
gmsh.finalize();
```

## Requirements

- macOS (Apple Silicon tested; Intel and Linux are untested but should work)
- MATLAB R2018a or newer (uses the `-R2018a` interleaved-complex API)
- A gmsh install providing `gmshc.h` and `libgmsh`. Easiest on macOS:
  ```sh
  brew install gmsh
  ```

## Build

```sh
make GMSH_INC=/opt/homebrew/include GMSH_LIB=/opt/homebrew/lib
```

This produces `+gmsh/+internal/gmsh_mex.mexmaca64` (or your platform's
extension). The build is incremental: `make` only re-links when the C
sources change.

Override variables on the command line as needed:

| Variable | Default | Purpose |
|---|---|---|
| `MEX` | `mex` | path or name of the MATLAB MEX compiler driver |
| `GMSH_INC` | *(unset)* | directory containing `gmshc.h` |
| `GMSH_LIB` | *(unset)* | directory containing `libgmsh.{dylib,so,dll}` |
| `GMSH_SRC` | `../gmsh` | gmsh source clone (only needed by `make gen`) |

If you regularly use Homebrew, set them once in your shell:
```sh
export GMSH_INC=/opt/homebrew/include
export GMSH_LIB=/opt/homebrew/lib
```

## Usage

```matlab
addpath('/path/to/gmsh-matlab')
gmsh.initialize()
% ... use the API ...
gmsh.finalize()
```

The package is laid out as `+gmsh/<submodule>/<function>.m`, so every
function in `gmshc.h` is reachable as `gmsh.foo.bar(...)`. Per-function
`arguments` blocks handle defaults and type validation; the MEX layer
only does conversion.

See `tutorials/` and `examples/api/` for ports of the upstream gmsh
tutorials and examples.

## Regenerating

`+gmsh/+internal/gmsh_mex.c` and every `.m` wrapper are generated by
`gen_matlab.py` from gmsh's canonical API spec (`gen.py` + `GenApi.py`).
You only need to regenerate after upgrading gmsh:

```sh
make gen GMSH_SRC=/path/to/gmsh-source-clone
```

The repo doesn't vendor the gmsh source — point `GMSH_SRC` at a clone of
[the upstream repository](https://gitlab.onelab.info/gmsh/gmsh).

## Testing

`gen/validate.sh <name>` runs a tutorial or example port in a sandbox
and reports whether it ran cleanly:

```sh
gen/validate.sh t1
# [t1] RAN
```

To also byte-compare the output against the upstream Python wrapper,
activate a venv with `gmsh` installed and point `GMSH_SRC` at a gmsh
source clone (for the `.py` reference scripts):

```sh
GMSH_SRC=/path/to/gmsh-clone gen/validate.sh t1
# [t1] IDENTICAL (1 file(s))
```

Diff mode also runs `numdiff.py` for tokens that disagree only in
floating-point — see `gen/numdiff.py`.

When `GMSH_SRC` is set, the harness:
1. Runs the Python script in one temp dir.
2. Runs the MATLAB port in another temp dir.
3. Byte-compares every output file.
4. Falls back to numeric tolerance (default `1e-12`) for files that differ in bytes.
5. Reports `IDENTICAL`, `CLOSE`, `DIFFER`, or `MISSING`.

When unset, it runs only the MATLAB port and reports `RAN` / `matlab failed`.

See [examples/STATUS.md](examples/STATUS.md) for per-example test
results, plus documented caveats around macOS OpenMP conflicts and the
gmsh-build-identity issue (different libgmsh builds produce different
meshes for the same input).

## Known limitations

- **FLTK GUI calls don't work inside MATLAB on macOS** — gmsh wants the
  Cocoa main thread, which MATLAB already owns. Use `gmsh.write(...)`
  and launch the standalone `gmsh` binary separately.
- **OpenMP runtime conflict on macOS** — setting
  `General.NumThreads > 1` or `Mesh.Algorithm3D = 10` segfaults due to
  MATLAB's preloaded `libiomp5.dylib` clashing with gmsh's `libomp`.
- **Mesh output is not byte-identical between gmsh builds** — two
  different builds of the same gmsh release (e.g. Homebrew vs the pip
  wheel) produce ~1% different meshes for the same input because they
  bundle different OpenCASCADE, BLAS, METIS, etc.
